# Project learnings

- discovery: `SkillInvocationMessageComponent` uses process-global theme state; direct renderer tests need `initTheme()`, and uninitialized-theme failure-path checks must run in a fresh Bun process. source: codebase; scope: project-wide; persist: Skill; next: initialize theme before standalone renderer assertions or isolate the regression in a child process.
- discovery: expanded custom skill cards render the skill name and copied content, so assertions should target the references line or name instead of expecting a markdown heading. source: codebase; scope: project-wide; persist: Skill; next: use the references text for expanded renderer checks.
- discovery: `formatSkillPickerPreview` now renders row selection with a `[ ]` token, so preview assertions should include the checkbox text after stripping ANSI. source: codebase; scope: project-wide; persist: Skill; next: keep preview snapshots aligned with the picker row format.
- discovery: `$` autosuggest needs current editor content, not just session-local key history; prompt-start tests need both `onTerminalInput` and `getEditorText()` stubs because raw terminal input alone cannot reproduce the empty-editor case. source: codebase; scope: project-wide; persist: Skill; next: keep the empty-editor regression and stub editor text when testing prompt-start shortcuts.
- discovery: saved taskflow shortcuts do not infer the current session log automatically; if a flow needs session context it must receive `session_id` or `session_path`, otherwise the resolver will report `missing-source` and downstream phases will see an empty candidate list. source: taskflow; scope: project-wide; persist: supporting docs; next: pass the current session id/path explicitly or make the shortcut inject them.
- discovery: taskflow interpolation placeholders must reference declared args with `{args.*}`; a bare `{session_id}` placeholder stays unresolved and prevents the resolver from locating the session file. source: taskflow; scope: project-wide; persist: supporting docs; next: use `{args.session_id}` and re-run `pi taskflow compile` after editing the flow.
